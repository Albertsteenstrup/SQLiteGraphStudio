# Agent exploration implementation status

Status as of 23 September 2026. This report records implementation and verification evidence for the [design](agent-exploration-design.md), local MCP surface, and [acceptance plan](agent-exploration-validation.md). It is not a release sign-off. No A01–A38 scenario is certified complete by this report.

## Implemented and exercised

- **Local coding-agent MCP.** The bundled `StudioMCP` stdio helper discovers 61 tools and forwards scoped requests to the running app over its private local bridge. A real Codex CLI invocation using `gpt-6-luna` discovered the tools and called `studio_status`; it reported `appRunning=true` and `bridgeConnected=true`. The native stdio test also passed. A scratch app interaction confirmed the graph/data split, tab switching, opening a table from the graph, and `studio_show_tables` narrowing the visible graph to the requested tables. Claude Code has not been exercised; its CLI is not installed on this host. See [MCP implementation](../Sources/StudioMCP/) and [automation coordinator](../Sources/SQLiteGraphStudio/StudioAutomationCoordinator.swift).
- **Agent-selected, non-story presentation.** The replacement `database-explore` skill tells the agent to choose the visual treatment and amount of guidance that fits the request. Tools can make an immediate view change or prepare and control short captioned presentation points; no fixed user-story sequence is required. The agent can show application-related tables near one another without drawing a database relationship between them. Generated Codex and Claude skill copies are checked against their canonical source. The old `story-flows` skill and story-specific UI/playback code have been removed.
- **Workspace, ownership, and recovery foundations.** Workspaces use split graph/data panes by default and keep browsing state per tab. MCP contexts bind to a task and workspace; source IDs and view revisions guard requests. Tab ownership, task-scoped listing, reconnect tokens and bounded idempotency receipts prevent one coding task from taking over another task's workspace implicitly. Disconnect cleanup cancels or pauses transient activity. These are tested foundations, not proof of every multi-client, restoration, or focus scenario.
- **Inspection and display tools.** The catalog and implementation cover status/launch, source and workspace selection, schema search/description, declared relation discovery, graph visibility/selection/field expansion/key focus/camera/layout, temporary arrangements and annotations, table filtering and sorting, bounded row and cell reads, record navigation, read-only SQL jobs/results, presentation control, preferences, saved explanations and selected exports. Disconnected tables may be arranged nearby without asserting a relationship. Large query and export work is represented as cancellable jobs. MCP SQL remains read-only, including when the manually opened SQLite source is writable.
- **Bounded cell access and query jobs.** `studio_inspect_value` reads a database-side bounded slice of one selected cell and reports type, length, offset, and whether more content remains. `studio_run_query` returns a job handle promptly, with separate status, cancellation and bounded result retrieval. SQLite and PostgreSQL row, query and record reads enforce a hard materialization budget of 256 KiB per cell, 8 MiB per result page and 512 columns. Large individual values remain available through the bounded cell-inspection path. Native table grids omit oversized non-key cells, label them “Large value — inspect in slices,” and prevent editing them; the full value is not silently shown as complete. Result previews do not imply that a full result has been read or shown.
- **Safe native inspection of oversized cells.** The native table context menu offers “Inspect Cell Slice…” for oversized cells and disables full-record inspection when a row is incomplete. The inspector displays at most 4,096 units per slice and provides Previous/Next navigation. It checks the selected source and row context before paging so a changed selection cannot silently show a slice from a different cell. The focused native regression suite passed 4/4, including text and BLOB paging and stale-context cases.
- **Speech path.** Graph Studio owns captions, playback controls, view readiness and narration timing. A pinned Pocket TTS worker/provider and asset downloader stream generated audio; the previously built universal app included the Pocket runtime, which passed its source check. On the tested arm64 machine, the worker took about 23 seconds to start and produced its first PCM 46 ms after a synthesis request. A 3.12-second clip streamed in 0.785 seconds, with about 906 MiB peak worker RSS. This is a development-machine observation, not an 8 GB target-device result or a clean-install benchmark.
- **Preferences, artifacts, skills, and migration.** Preference tools and metadata migration exist; saved explanations preserve historical bounded evidence and can be reopened separately from refresh. The setup sheet defaults to user-wide setup and allows a reviewed project-folder option. Its read-only preflight shows client CLI versions and planned MCP/skill changes; install runs only after the user approves the preview. Project skills stay under the selected folder, Claude Code writes its project `.mcp.json` through its CLI, and Codex uses the project's `.codex/config.toml`; symlinked config or skill destinations are refused. After configuration read-back, setup launches the exact bundled helper to check MCP initialization, discover tools, and call read-only `studio_status`, reporting whether the app bridge is actually connected. This verifies the helper and its current app status, not that an already-running agent session has reloaded the connection. Generated skill resources retain the graph-clusters, schema-descriptions, database-preview, and database-diff workflows. Migration tests exercise removal of legacy story metadata while retaining unrelated values. First-use preference discovery and adaptation still need native end-to-end validation.

## Known product and release limits

- **No synchronized Codex Voice presentation.** The local MCP can accompany a Codex conversation with Graph Studio views, and Graph Studio can narrate its own points. The bridge does not receive Codex microphone, generated-audio timing, or interruption events, so synchronized speech and graph timing, including reliable user barge-in across both products, is not implemented or demonstrated. Treat them as separate conversation and presentation paths.
- **No Claude Code live result yet.** The setup preflight reports that Claude Code is unavailable on this host. Installer and skill-output behavior are covered by tests, but a real Claude Code installation and its protocol behavior have not been checked.
- **Speech distribution and target device are open.** The measured worker run does not establish first-run download/install UX, clean-machine execution, voice quality, long-session memory, interruption latency, or acceptable performance on an 8 GB Apple Silicon Mac. Intel builds use the macOS speech fallback because the pinned PyTorch runtime does not support the Intel target used here.
- **Some tool behavior is narrower than the design.** Current limits include single-column sorting, offset-based paging, no SQL-parameter interface, no general historical navigation beyond explicit captured checkpoints, no presentation speed control, and limited history pagination. MCP responses have a 1 MiB serialized-response cap; SQLite and PostgreSQL row/query/record materialization enforce separate 256 KiB per-cell, 8 MiB per-page and 512-column hard limits. Native grids omit oversized non-key values and mark them for slice inspection. Check tool schemas and result limits before claiming broader contracts.
- **Saved explanation and export scope is bounded.** Historical replay restores captured graph/layout/table selections and shows the captured table/query pages referenced by the current point. It reads only the offline artifact; pages with no point reference remain visible in the manual historical view. MCP export supports bounded CSV/JSON rows and transcripts; graph images and a packaged explanation export are not implemented through `studio_export`.
- **Interaction/accessibility coverage remains incomplete.** Keyboard and screen-reader paths, reduced motion, manual graph manipulation during narration, concurrent task/tab focus, and all failure/recovery paths need native testing. Multi-million-row paging and many-table scenarios have not yet been combined with simultaneous tabs, client activity, and speech in a release build.
- **Distribution signing is unavailable here.** The previously built app and DMG are unsigned and unnotarized because this host has no Developer ID signing identity. Signing, notarization, clean installation on a separate Mac, and public distribution therefore remain external release steps.
- **PostgreSQL dump runtime packaging is open.** The current package does not include a self-contained redistributable PostgreSQL restore/runtime bundle. That optional capability requires a separately prepared universal relocatable runtime and release validation.

## Release assessment

The worktree now has a substantial working MCP, graph/data workspace, bounded inspection/query paths, local narration, and meaningful automated plus native smoke evidence. The latest isolated Swift Testing run is green, but the latest source changes have not yet been packaged into a final universal artifact. This report does **not** certify the requested product complete or ready for public distribution. Remaining release gates include rebuilding and verifying the package, code signing and notarization, clean installation on a separate Mac, testing on an 8 GB Apple Silicon Mac, real Claude Code use, PostgreSQL dump runtime packaging if that capability is part of the release, and complete native acceptance scenarios. Codex Voice synchronization remains unsupported: Graph Studio narration is available, while shared audio timing and cross-product interruption are not implemented or validated.

For the complete expected scenario set, target-device measurements and validation method, see the [acceptance plan](agent-exploration-validation.md).
